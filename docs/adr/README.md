# Architecture Decision Records

ADRs capture decisions that should not be silently overturned by implementation.

Status values: `Proposed`, `Accepted`, `Superseded`, `Rejected`.

A superseding decision adds a new ADR or explicitly updates the old ADR with links and migration/rollback implications. ADRs describe **why** and the durable constraints; implementation details that may change routinely belong in architecture docs/code.

Initial accepted decisions are numbered in creation order and intentionally keep the project small.
